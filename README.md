## 🧠 I Like Going Deep

One thing that strongly defines how I learn is that I don't like stopping at the API level.

If I'm learning **Redis**, I want to understand:

`Commands → Atomicity → Event Loop → MULTI/EXEC → Lua → Data Structures → Persistence → Replication → Failure Modes`

If I'm learning **Kafka**:

`Producer → Partitions → Replication → Consumer Groups → Offsets → Rebalancing → Ordering → Delivery Semantics`

If I'm learning **MySQL**:

`SQL → Optimizer → Indexes → B+ Trees → Buffer Pool → MVCC → Undo Logs → Transactions → Isolation Levels → Locking`

If I'm learning **distributed systems**:

`Consistency → Replication → Partitioning → Failure → Consensus → Ordering → Availability → Trade-offs`

And if I'm learning **AI systems**:

`LLMs → Tokens → Context → RAG → Vector Search → Tool Calling → Agents → MCP → Evaluation → Production Architecture`

I enjoy connecting these concepts to **real production problems** rather than learning them in isolation.

I don't believe in simply collecting technologies.

My learning loop usually looks something like:

```text
                    ┌──────────────────┐
                    │   Learn a Tech   │
                    └────────┬─────────┘
                             ↓
                    ┌──────────────────┐
                    │ Understand Why   │
                    └────────┬─────────┘
                             ↓
                    ┌──────────────────┐
                    │ Go Under the Hood│
                    └────────┬─────────┘
                             ↓
                    ┌──────────────────┐
                    │ Read Real-World  │
                    │    Architectures │
                    └────────┬─────────┘
                             ↓
                    ┌──────────────────┐
                    │ Build / Experiment│
                    └────────┬─────────┘
                             ↓
                    ┌──────────────────┐
                    │ Understand Trade │
                    │      -offs       │
                    └────────┬─────────┘
                             ↓
                    ┌──────────────────┐
                    │ Apply at Work /  │
                    │  Build Something │
```

I'm especially interested in the **trade-offs** behind engineering decisions:

> Why Kafka instead of a synchronous API?

> Why Redis instead of a database query?

> When does caching make things worse?

> Why does an index sometimes get ignored?

> What actually happens when a transaction reads an old version of a row?

> What happens when a Kafka consumer crashes halfway through processing?

> How does an LLM agent actually interact with external systems?

Those questions are what keep me curious.
